# ブログ v0（2026-11-23）

- 状態: 試作。前段のアプリの後ろ（server.md §6）で、記事を書いて公開する最小の形
- 実装: `packages/server/Blog.php`・`Api.php`（一覧・題名と日付・画像）、`packages/editor/posts.html`・`posts.mjs`・`posts-core.mjs`、`editor.mjs`（記事の切り替え・題名と日付・画像を選ぶ）

## 1. 何ができるか

- 記事の一覧（`posts.html`）で、題名と日付を入れて新しい記事を書き始める。一覧から記事を開いて直す
- エディタの上の欄で、記事の題名と日付を直す。公開中の記事なら、公開中のページの題名と目次もすぐ直る
- 画像の部品で「画像を選ぶ…」を押すと、画像を送って入れる。写真は送る前に長い辺 1600px の JPEG にする（1MB 以下の PNG と GIF はそのまま）
- 公開・公開の取り消し・題名や日付の変更のたびに、ブログの目次（`index.html`）とフィード（`feed.xml`、RSS 2.0）を作り直す

## 2. 決めたこと

- **ブログは設定で入れる。** `WGE_BLOG_TITLE` があるときだけブログになる。このとき `top` は目次（サーバーが作るページ）で、編集できない（`/api/pages/top/*` は 404）。エディタを `top` で開くと記事の一覧へ移る
- **記事の id は日付と 4 桁の 16 進数**（`20261123-a3f9`）。URL は `<サイト>/<id>/`
- **題名と日付は `page_meta` に持つ。** 保存の規則（`PageStore`・`fixtures/store.json`）には手を入れない。題名は 1 行で 1〜120 文字、日付は実在する `YYYY-MM-DD`
- **目次はソース形式で書いて、ほかのページと同じ書き出しを通す。** 見た目が記事と揃い、属性とクラスの検査（R4）もそのまま効く。題名の `& < > "` は文字参照にする
- **画像は中身のバイトで種類を見分ける**（JPEG・PNG・GIF・WebP）。SVG はスクリプトを含められるので受け付けない。名前は中身の SHA-256 の先頭 16 桁で、同じ画像は 1 つだけ置く。2.5MB まで。`media/` に置き、記事からは `../media/<名前>` で指す（記事は 1 段下のフォルダにあるため）。エディタのプレビューも 1 段下（`/editor/`）にあるので、同じ書き方で見える（前段の入口は `/media/` を配る）
- **フィードの日付は日本時間の 0 時。** `WGE_SITE_URL` が無いと、フィードは作らない

## 5. 記事の削除（2026-11-24）

- **削除はゴミ箱へ移すこと。** 下書き・版・題名と日付は消さない。`page_trash` に削除した時刻を持つ。完全に消す操作はまだ作らない
- 公開中の記事を削除すると、その場でサイトから消す（記事のページとフォルダ）。目次とフィードも作り直す。版の記録は残すので、戻したあとに公開し直せる
- **戻すと下書きに戻る。** 戻しただけでは公開しない。公開し直すかは書いた人が選ぶ
- ゴミ箱の記事は `restore` 以外のすべての要求（`load`・`draft`・`meta`・`publish`・版の読み出し・`delete`）に 404 `deleted` を返す。別のタブで開いたままのエディタは保存できなくなり、そのことを表示する。エディタをゴミ箱の記事で開いたときも、ブラウザの中への保存に切り替えずに止まる
- `media/` の画像は消さない。名前は中身のハッシュで、ほかの記事も同じ画像を指している場合がある
- ブログでないサイトの `top` はサイトそのものなので、削除できない（422 `protected`）
- 画面（`posts.html`）：各記事の「削除」。公開中の記事だけ、サイトから消えることを確認してから消す。消したあとの「元に戻す」と、一覧の下のゴミ箱（件数つき、「戻す」）
- 前段のアプリ（server.md §6）は、`delete` と `restore` を中継する道を別に許す必要がある。サイトから消えるので、公開と同じ権限に揃えるのがよい
- テスト（`test.php` part 5）：要求ヘッダーの検査、公開中の記事の削除でページとフォルダが消えること、目次とフィードの書き直し、一覧とゴミ箱、ゴミ箱の記事が 6 種の要求を断ること、戻すと下書きで一覧に戻り公開されないこと、戻した記事の公開、読み込まれていない記事、ブログでない `top`

## 6. 説明文と共有の印（2026-11-24）

- **説明文は `page_meta.description` に持つ。** 1 行で 300 文字まで（前後の空白は取る）。空なら書かない。前の版のデータベースには、開いたときに列を足す
- エディタでは、題名と日付の横の「説明文」から書く。改行は空白にする。書いた後は ✓ が付く
- 公開するページの `<head>` には、rendering.md §5 の `head` を渡す
  - `description`：その記事の説明文
  - `url`：`WGE_SITE_URL` があるときだけ。記事は `<サイト>/<id>/`、目次は `<サイト>/`。無ければ説明文の `<meta>` だけを書く（開発用の `router.php` はこちら）
  - `type`：ブログの記事は `article`、目次とブログでないサイトは `website`
  - `siteName`：ブログの名前
  - `image`：ページの中の最初の画像の部品の `src` を、記事の URL を基準に絶対 URL にしたもの（`../media/x.png` → `<サイト>/media/x.png`）。`javascript:` などの方式、`//` で始まるもの、空白や `"` を含むものは使わない
- フィードの各記事に、説明文があれば `<description>` を付ける
- 記事の一覧の API（`GET /api/pages`）も `description` を返す
- テスト（`test.php` part 5）：説明文の検査（改行・301 文字・文字列でない値）、前後の空白、題名だけの変更で説明文が残ること、記事と目次の `<head>`、最初の画像の絶対 URL、フィード、一覧、URL の解決 8 通り、前の版のデータベースへの列の追加。書き出し器の共通テストデータに `head` の 10 件（JS・PHP）

## 7. 画像の幅と高さ（2026-11-24）

- 画像の部品に任意の `width` `height`（1〜20000 の整数）を足した（schema.json）。書き出しでは `<img>` の `width` `height` になる。画像が読み込まれる前からその縦横比で場所を取るので、読み込みで下の文が動かない（CLS）
- `POST /api/media` は、画像の先頭（ヘッダー）から読んだ幅と高さを返す。読めない画像は寸法なしで保存する。エディタは画像を選ぶと `src` と一緒に寸法を入れ、寸法が返らなければ前の画像の寸法を消す
- 既存の記事の画像には寸法がない。そのままでも表示は変わらない
- `ratio="auto"` のクラスは `aspect-ratio: auto` から `width: auto` に変えた。`aspect-ratio: auto` は、ブラウザが `width` `height` から作る縦横比を打ち消してしまうため（共通テストデータの `default.css` も同じに直した）。`1:1` などの指定は、これまでどおり切り抜いて表示する
- 無作為テストの R4 の検査で許す属性に `width` `height` を足した。種 7・11・23 で各 2 万件、PHP 8.3 と 8.5 で食い違い 0 件、不変条件の違反 0 件（種 7 の出力に寸法付きの `<img>` が 1,145 件）
- エディタの画像の欄：`width` `height` は「元の幅（px）」「元の高さ（px）」の数字の欄（区画の「中身の幅」と名前が同じなので、部品ごとの名前を持つようにした）。範囲の広い整数は、選ぶ一覧でなく数字の欄にする
- **区画の幅を画像にも効かせた（前からあった不具合）。** `.wge-image { max-width: 100% }` が区画の `.wge-width-narrow > *` より後ろにあり、区画の直下の画像は本文の列より広く出ていた。区画の幅は `min(100%, 幅)`、`full` は `100%` にし、画像の `max-width: 100%` は重みのない `:where(.wge-image)` に移した
- アプリ内のブラウザで確かめたこと（`editor-blog`、1024px と 375px）
  - 記事を作り、説明文を書くと保存され「説明文 ✓」になる
  - 画像の部品を足し、canvas で作った 800×450 の PNG を「画像を選ぶ」の処理に渡すと、元の幅 800・高さ 450 が入る。公開ページの `<img>` に `width="800" height="450"`、`<head>` に説明文
  - 1024px で画像が本文の列（640px）に揃う。375px で 343×193（16:9 を保つ）、横スクロールなし。画像の読み込み前から場所を取る（`aspect-ratio: auto 800 / 450`）
  - 下書きの削除 →「元に戻す」で一覧に戻る。公開中の記事の削除は確認が出て、キャンセルなら何もしない。確認を受けると公開ページが 404、目次から消え、ゴミ箱に 1 件。ゴミ箱の記事をエディタで開くと案内を出し、ボタンを押せなくして止まる（ブラウザの中への保存に切り替えない）。「戻す」で下書きとして一覧に戻る
  - 確認ダイアログの「はい」は、アプリ内のブラウザが自動でキャンセルにするため、`confirm` をテスト用に差し替えて押した
