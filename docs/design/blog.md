# ブログ v0（2026-11-23）

- 状態: 試作。前段のアプリの後ろ（server.md §6）で、記事を書いて公開する最小の形
- 実装: `packages/server/Blog.php`・`Api.php`（一覧・題名と日付・画像）、`packages/editor/posts.html`・`posts.mjs`・`posts-core.mjs`、`editor.mjs`（記事の切り替え・題名と日付・画像を選ぶ）

## 1. 何ができるか

- 記事の一覧（`posts.html`）で、題名と日付を入れて新しい記事を書き始める。一覧から記事を開いて直す
- エディタの上の欄で、記事の題名と日付を直す。公開中の記事なら、公開中のページの題名と目次もすぐ直る
- 画像の部品で「画像を選ぶ…」を押すと、画像を送って入れる。写真は送る前に長い辺 1600px の JPEG にする（1MB 以下の PNG と GIF はそのまま）
- 公開・公開の取り消し・題名や日付の変更のたびに、ブログの目次（`index.html`）とフィード（`feed.xml`、RSS 2.0）を作り直す
- 記事の一覧で、下書きの記事を「削除」する。消した記事は一覧の下の「削除した記事」に移り、「元に戻す」で下書きとして戻る（2026-11-24）

## 2. 決めたこと

- **ブログは設定で入れる。** `WGE_BLOG_TITLE` があるときだけブログになる。このとき `top` は目次（サーバーが作るページ）で、編集できない（`/api/pages/top/*` は 404）。エディタを `top` で開くと記事の一覧へ移る
- **記事の id は日付と 4 桁の 16 進数**（`20261123-a3f9`）。URL は `<サイト>/<id>/`
- **題名と日付は `page_meta` に持つ。** 保存の規則（`PageStore`・`fixtures/store.json`）には手を入れない。題名は 1 行で 1〜120 文字、日付は実在する `YYYY-MM-DD`
- **目次はソース形式で書いて、ほかのページと同じ書き出しを通す。** 見た目が記事と揃い、属性とクラスの検査（R4）もそのまま効く。題名の `& < > "` は文字参照にする（2026-11-24 に、見出しの帯だけをソース形式にし、記事の並びはサーバーが書く形に変えた。§7）
- **画像は中身のバイトで種類を見分ける**（JPEG・PNG・GIF・WebP）。SVG はスクリプトを含められるので受け付けない。名前は中身の SHA-256 の先頭 16 桁で、同じ画像は 1 つだけ置く。2.5MB まで。`media/` に置き、記事からは `../media/<名前>` で指す（記事は 1 段下のフォルダにあるため）。エディタのプレビューも 1 段下（`/editor/`）にあるので、同じ書き方で見える（前段の入口は `/media/` を配る）
- **フィードの日付は日本時間の 0 時。** `WGE_SITE_URL` が無いと、フィードは作らない
- **削除できるのは公開していない記事だけ。** 公開中の記事は、先にエディタで公開を取り消す。こうすると、削除でサイトが変わることはない。公開中かどうかの確かめと削除の書き込みは同じ書き込みの鍵の中で行うので、あいだに公開が入ることもない
- **削除は「一覧から外す」だけで、中身は消さない。** 下書き・版・題名と日付は残し、`deleted_pages` に id と時刻を足す。消した記事は元に戻すまで、どの操作にも 404 `deleted` を返す（読み込み直しで作り直されることもない）。画像（`media/`）は他の記事と共有しうるので消さない。データベースから本当に消す操作は、まだ無い
- **削除の前に確かめを出さない。** 元に戻せるので、代わりに削除のあとで「元に戻す」を出す
- **`top` は削除できない**（409 `top`）。ブログでないサイトでは、エディタが既定で開くページのため。ブログの `top` はもともと 404

## 3. API（server.md §2.1 に足したもの）

| 要求 | 本文 | 成功 | 失敗 |
|---|---|---|---|
| `GET /api/pages` | — | 200。`pages`（id・title・date・published・savedAt。日付の新しい順） | — |
| `POST /api/pages/{id}/load` | `initialSource`、`meta`（任意。`title`・`date`） | 200。`meta` も返す | 422（`invalid-title`・`invalid-date`） |
| `POST /api/pages/{id}/meta` | `title`、`date`、`description`（任意。無ければ今のまま） | 200 | 404（読み込まれていない）、422（`invalid-title`・`invalid-date`・`invalid-description`） |
| `POST /api/media` | `data`（base64） | 200。`src`、読めれば `width`・`height` | 413 `too-large`、415 `not-image`、400 |
| `GET /api/ping` | — | ブログなら `blog: true`・`blogTitle` も返す | — |
| `POST /api/pages/{id}/delete` | `{}` | 200。`deletedAt`（ミリ秒） | 409 `published`（公開中）・`top`、404 `not-loaded`・`deleted` |
| `POST /api/pages/{id}/restore` | `{}` | 200。`draft`・`published`（`load` と同じ形） | 409 `not-deleted`、404 `not-loaded` |
| `GET /api/deleted-pages` | — | 200。`pages`（id・title・date・deletedAt。削除の新しい順） | — |

削除した記事への `load`・`draft`・`publish`・`undo-publish`・`meta`・`delete` と版の読み出しは、404 `deleted` になる。

## 5. 説明文と共有の印（2026-11-24）

- **説明文は `page_meta.description` に持つ。** 1 行で 300 文字まで（前後の空白は取る）。空なら書かない。前の版のデータベースには、開いたときに列を足す
- エディタでは、題名と日付の横の「説明文」から書く。改行は空白にする。書いた後は ✓ が付く
- 公開するページの `<head>` には、rendering.md §5 の `head` を渡す
  - `description`：その記事の説明文
  - `url`：`WGE_SITE_URL` があるときだけ。記事は `<サイト>/<id>/`、目次は `<サイト>/`。無ければ説明文の `<meta>` だけを書く（開発用の `router.php` はこちら）
  - `type`：ブログの記事は `article`、目次とブログでないサイトは `website`
  - `siteName`：ブログの名前
  - `image`：ページの中の最初の画像の部品の `src` を、記事の URL を基準に絶対 URL にしたもの（`../media/x.png` → `<サイト>/media/x.png`）。`javascript:` などの方式、`//` で始まるもの、空白や `"` を含むものは使わない
- フィードの各記事に、説明文があれば `<description>` を付ける
- 記事の一覧の API（`GET /api/pages`）も `description` を返す
- テスト（`test.php` part 5）：説明文の検査（改行・301 文字・文字列でない値）、前後の空白、題名だけの変更で説明文が残ること、記事と目次の `<head>`、最初の画像の絶対 URL、フィード、一覧、URL の解決 8 通り、前の版のデータベースへの列の追加。書き出し器の共通テストデータに `head` の 10 件（JS・PHP）

## 6. 画像の幅と高さ（2026-11-24）

- 画像の部品に任意の `width` `height`（1〜20000 の整数）を足した（schema.json）。書き出しでは `<img>` の `width` `height` になる。画像が読み込まれる前からその縦横比で場所を取るので、読み込みで下の文が動かない（CLS）
- `POST /api/media` は、画像の先頭（ヘッダー）から読んだ幅と高さを返す。読めない画像は寸法なしで保存する。エディタは画像を選ぶと `src` と一緒に寸法を入れ、寸法が返らなければ前の画像の寸法を消す
- 既存の記事の画像には寸法がない。そのままでも表示は変わらない
- `ratio="auto"` のクラスは `aspect-ratio: auto` から `object-fit: fill`（初期値と同じで、見た目は変わらない）に変えた。`aspect-ratio: auto` は、ブラウザが `width` `height` から作る縦横比を打ち消してしまうため。幅 300px の箱に 800×450 の画像（読み込み前）を置いて比べると、比率の指定なしは 300×169、`aspect-ratio: auto` は 300×0、途中で試した `width: auto` は 0×0、`object-fit: fill` は 300×169（共通テストデータの `default.css` も同じに直した）。`1:1` などの指定は、これまでどおり切り抜いて表示する
- 無作為テストの R4 の検査で許す属性に `width` `height` を足した。種 7・11・23 で各 2 万件、PHP 8.3 と 8.5 で食い違い 0 件、不変条件の違反 0 件（種 7 の出力に寸法付きの `<img>` が 1,145 件）
- エディタの画像の欄：`width` `height` は「元の幅（px）」「元の高さ（px）」の数字の欄（区画の「中身の幅」と名前が同じなので、部品ごとの名前を持つようにした）。範囲の広い整数は、選ぶ一覧でなく数字の欄にする
- **区画の幅を画像にも効かせた（前からあった不具合）。** `.wge-image { max-width: 100% }` が区画の `.wge-width-narrow > *` より後ろにあり、区画の直下の画像は本文の列より広く出ていた。区画の幅は `min(100%, 幅)`、`full` は `100%` にし、画像の `max-width: 100%` は重みのない `:where(.wge-image)` に移した
- アプリ内のブラウザで確かめたこと（`editor-blog`、1024px と 375px）
  - 記事を作り、説明文を書くと保存され「説明文 ✓」になる
  - 画像の部品を足し、canvas で作った 800×450 の PNG を「画像を選ぶ」の処理に渡すと、元の幅 800・高さ 450 が入る。公開ページの `<img>` に `width="800" height="450"`、`<head>` に説明文
  - 1024px で画像が本文の列（640px）に揃う。375px で 343×193（16:9 を保つ）、横スクロールなし。画像の読み込み前から場所を取る（`aspect-ratio: auto 800 / 450`）
  - 削除した記事をエディタで開くと、案内を出してボタンを押せなくして止まる（ブラウザの中への保存に切り替えない。§2 の削除に足した）

## 7. 見た目（2026-11-24）

ブログが素のページ（青い既定の色・題名のリンクだけの目次・記事に日付も戻り道もない）だったので、次のように整えた。サイト全体のヘッダー・ナビ・フッターは site.md の共通の部分で入れるので、ここでは入れていない。

- **目次**
  - 見出しの帯：ブログの名前を、テーマの主な色の帯（`Section background="primary"`）に置く。ソース形式で書く
  - 記事の並び：各記事の日付（`<time datetime>`）・題名・説明文（2 行まで）・最初の画像を、新しい順に並べる。行のどこを押しても記事が開く（題名のリンクを CSS で行いっぱいに広げる。読み上げでは題名のリンクだけ）
  - 画像は記事の中の最初の Image。エディタが入れた画像（`../media/<16 桁>.<jpg|png|gif|webp>`）は目次から見た `media/…` に直し、`http(s)://` の絶対 URL はそのまま、それ以外（`/` で始まるもの・`//`・ほかの方式）は出さない（`Api::contentsImageOf`）。題名の横に出すので `alt=""`
  - フィード（`WGE_SITE_URL` があるとき）へのリンクを並びの下に置く
  - 記事が 0 件なら「まだ記事はありません。」
- **記事**：本文の前に「‹ ブログの名前」（目次へ）と日付、本文の後に「‹ 記事の一覧へ」を置く。題名は本文の見出しのまま（雛形が本文の先頭に H1 を入れるため、二重にしない）。本文の中見出し（H2）は主な色の下線つき
- **書き方**：並びと記事の枠は、サーバー（`Blog.php`）が決まったクラスで書き、値はすべて文字参照にする。題名や説明文がマークアップになることはない。`renderPage` の出力の `<main class="wge-page">` の中の先頭と末尾に差し込む（書き出し器は変えていないので、JS と PHP の出力の一致はそのまま）
- **CSS**：`base.css` に、見出しの大きさ（H1〜H3）と、`wge-posts-*`・`wge-post-*` のクラスを足した。色はテーマの変数と `color-mix()` だけで作り、テーマの項目は増やしていない
- **テーマ**：`WGE_DATA/theme.json` があればそれを使う（rendering.md §4、server.md §6.2）。エディタのプレビューも `source/theme.json` で同じテーマを読む。中見出しの下線は公開ページの記事の枠に付けているので、プレビューには出ない
- **すでに公開しているページ**は、次の公開まで古い見た目のまま。版を上げたりテーマを変えたりしたら、`php packages/server/trusted-front.php --rebuild` を同じ設定（環境変数）で流すと、公開中の全ページ・目次・フィード・`style.css` を書き直す。下書きとデータベースは変えない（`Api::rebuildSite`）
- テスト（`test.php` part 5）：目次の帯・各記事の日付と題名（文字参照）・本文に `</main>` があっても枠が最初の `<main>` と最後の `</main>` に入ること・説明文と画像・画像も説明文もない記事・フィードへのリンクが `<main>` の最後にあること、記事の枠（目次への道と日付・一覧へ戻るリンク・本文がその間にあること）、目次に出す画像の 10 通り、テーマを変えての書き直し（`style.css` の色・消えた記事の復元・下書きが変わらないこと・目次の画像）。前段（`Front`）がテーマを `source/theme.json` で配ること（テーマなしは既定、署名なしは 403）
- 手元で確かめたこと：開発用サーバー（`run-dev.sh` にブログの名前、`data/blog/theme.json` に緑のテーマ）に見本の記事 4 件を入れ、1280px と 375px で目次と記事を表示した。ui-audit で小さすぎる押し領域・コントラスト不足・横はみ出しが 0、見出しの順の飛びなし。375px で説明文を押すと記事が開く。Tab の最初は 1 件目の題名。コンテナの中で `--rebuild` が 4 件を書き直し、壊れた `theme.json` と鍵なしでは終了コード 1
