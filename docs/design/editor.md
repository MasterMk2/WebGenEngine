# ブラウザのエディタ（v0 試作）

- 状態: 試作。R4（ソースと GUI の双方向）と R5（ドラッグを座標ではなく「意図」として保存する）を、画面の上で確かめるためのもの
- 実装: `packages/editor/`
  - `index.html`、`editor.css`、`editor.mjs`: 画面
  - `slots.mjs`: ドラッグを「どこに入れるか」に変える計算。DOM を使わない関数だけにして、node でテストする（`slots.test.mjs`）
- `inline-dom.mjs`: プレビューの上で書いた文を、ソース形式の文（文字、Strong、Em、Link、Br）に読み戻す。node でテストする（`inline-dom.test.mjs`）
  - `serve.mjs`: 手元で開くためのサーバー（127.0.0.1 だけで待ち受ける）
  - `sample/`: 手で書いたサンプルのページと仮の画像
- `packages/source/` のパーサー、編集操作、書き出し器をそのまま読み込む。エディタ用の写しは作らない

動かし方（リポジトリの直下で実行する）:

```bash
node packages/editor/serve.mjs
```

ブラウザで `http://127.0.0.1:8765/editor/` を開く。テストは次のとおり。

```bash
node --test packages/editor/slots.test.mjs packages/editor/inline-dom.test.mjs
```

## 1. 画面

- 左: プレビュー。部品をクリックすると選び、ドラッグすると並べ替える。PC 幅とスマホ幅（375px）を切り替えられる
- 右上: 選んだ部品の設定。属性の欄は `schema.json` から作る（選択肢のある属性は選択欄、`int` は範囲内の選択欄、`url` と `string` は入力欄）。必須でない属性には「指定なし」がある
  - 文の中身（見出し、文章、ボタンの文字）は、プレビューの上でクリックした場所からそのまま書く（editor-ux.md §3.2。2026-10-29 から）。太字（Ctrl+B）と斜体（Ctrl+I）も付けられる。リンクの追加はまだソースで行う
  - 「親を選ぶ」「前へ」「後ろへ」「削除」。ドラッグを使わなくても並べ替えられる
- 右下: ソース。書き換えると 0.3 秒後に読み直してプレビューに反映する
  - エラーがあれば行と列を出し、プレビューは最後に読めた内容のまま薄く表示する。エラーの間は GUI からの操作を止める（打ちかけのソースを上書きしないため）
  - ソース上のカーソル位置にある部品を、プレビューでも選ぶ。逆に、プレビューで選んだ部品はソースの該当範囲に色を付ける
  - 前の操作で何行変わったか（行の差分で数えた削除と追加の行数）を出す
- 元に戻す、やり直す（Ctrl+Z、Ctrl+Y）。ソースの文字列を履歴として持つ

## 2. 状態の持ち方

ソースの文字列だけを状態とする。GUI の操作ごとに次のことをする。

1. いまのソースを読む
2. 編集操作（`source-format.md` §9）を 1 つ行う
3. 触っていない部分を残す保存（同 §8）で書き出す
4. 書き出したものを読み直し、編集後のツリーと同じになることを確かめる。違えば保存せずにエラーを出す

こうすると、ソースの範囲の情報が常に最新になり、無作為テストの不変条件（編集後の出力は編集後のツリーに読み直せる）を画面の上でも毎回確かめられる。

## 3. ドラッグと意図

ドラッグを離したときに保存するのは「どの箱の、何番目に入れるか」だけで、座標は保存しない（要件 §3.1）。

- 入れ先の箱: ポインターの下にある箱（`container`）のうち、いちばん内側のもの。動かしている部品の中には入れない
- 箱の端（親の並びの向きに沿って、最大 24px か、箱の大きさの 1/4）では、その箱の中ではなく隣に入れる。カードの上で離したときに、カードの中に入ってしまうのを防ぐため
- 何番目か: 縦の並び（区画、縦の Stack、ページ）は子の上下の中心と比べる。横の Stack と Grid は、まず行を決め、その行の中で左右の中心と比べる
- ドラッグ中は、入れ先の箱を枠で、入る位置を線で示し、「並び → 格子の 2 番目」のように言葉でも示す
- 選んでいる部品の中からドラッグすると、その部品ごと動く。いちばん内側の部品ではなくカード全体を動かしたいときは、クリックしてから「親を選ぶ」でカードを選び、ドラッグする
- 編集操作の `move` は、取り外した後のツリーで位置を数える。画面上の位置からの変換は `slots.mjs` の `moveArgs` が行う。小さなツリーのすべての移動先について、`move` の結果が「取り外して、同じ隣の前に入れる」と一致することをテストで確かめている

## 4. プレビューの作り

- プレビューは `srcdoc` の iframe に出す。`sandbox="allow-same-origin"` で、プレビューの中のスクリプトは動かない
  - iframe にするのは、Grid が 1 列になる切り替えが画面幅の media query で書かれているため。エディタの画面の中に直接描くと、プレビューの幅を狭めても切り替わらない
  - 公開用の CSS がエディタの画面に効かないようにする意味もある
- 書き出し器（`render.mjs`）の `renderFragment(doc, indent, { annotate: true })` で、各部品に `data-wge-path`（ツリーでの位置）を付ける。位置はコメントも数えるので、DOM の順番からは求めない
  - 公開ページの書き出しでは付けない。既定は付けない設定で、共通テストデータ 121 件は変更前と同じく通る
- Html の箱は、プレビューでは中身を出さずに「Html」と書いた枠にする。中身を出すと、`<img onerror>` のような書き方でエディタの画面の中でスクリプトが動きうるため
- プレビューの上に透明な層を重ね、クリックとドラッグはそこで受ける。プレビューのリンクを押しても移動しない。ホイールの回転はプレビューに渡してスクロールさせる

## 5. 確かめたこと（2026-10-29、アプリ内のブラウザ、1440×900 相当）

- 手書きのサンプル（字下げが 4 つの空白の部分があり、属性の順番もスキーマと違う）で、Grid の 3 番目のカードを先頭にドラッグした
  - ソースで変わったのは、カードの 5 行の位置だけ（−5 行 +5 行）。ほかの行は 1 文字も変わらず、字下げも属性の順番も元のまま
  - 「元に戻す」で、元のサンプルと 1 文字も違わないソースに戻る
- 見出しの段階を変えると、その行の開始タグだけが正規形で書き直される（1 行）
- ボタンを上の区画から下の区画へドラッグすると、移動先の字下げに合わせて入る
- ソースに存在しない部品名を書くと「5 行 5 列: <Txt> という部品はありません」と出て、GUI の操作は止まる。直すとプレビューに反映される
- ソースのカーソル位置の部品がプレビューで選ばれる
- スマホ幅（375px）で Grid が 1 列になり、横スクロールは出ない
- 部品の追加、文字の変更、削除
- コンソールのエラーはなし

## 6. まだしていないこと

- 揃え先のガイドと吸着、ずれの一覧（R5 の表の 8px、4px、25% の判定）。いまの形式では位置を座標で持たないので、ずれは保存されない。ずれの一覧が役に立つのは、主に WordPress のテーマを取り込むとき（要件 §3.5）なので、その段階で作る
- 中身のない箱に新しく入れた部品の字下げは、空白 2 つになる（ファイルの他の部分が 4 つでも）。元の字下げの幅から推定する処理は、PHP 版の保存処理と一緒に直す必要がある
- 文の中にリンクを GUI で足すこと（太字と斜体はプレビューの上で付けられる）
- タッチ操作での確認。Pointer Events で書いているが、スマートフォンの実機では試していない。プレビューの上ではタッチによるスクロールもできない
- キーボードだけでのドラッグの代わり（選んだ部品のツールバーの ↑↓ と Alt+↑↓ はあるが、別の箱へ移す操作がない）
- キーボードだけで文字を直すこと。右の欄の文字の入力欄をやめたので、プレビューの部品をキーボードで選べるようになるまで（editor-ux.md §4.3）、ソースで直すしかない
- 保存先のサーバー。下書き・公開・版の扱いは `store.mjs` に作ったが（editor-ux.md §3.8）、中身はブラウザの localStorage で、サーバーには送らない
- Html の中身を書けるのを管理者だけにする仕組み（rendering.md §7）
