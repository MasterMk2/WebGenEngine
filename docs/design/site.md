# サイトのページと共通の部分（v0・2026-11-24）

- 状態: 試作。ブログでない「サイト」を WGE で持つための最初の段
- 実装: `packages/server/Site.php`・`Api.php`（書き出し先・書いたファイルの台帳・共通の部分）、`packages/source/js/render.mjs`・`php/Renderer.php`（`renderPage` の `header`・`footer`）、`packages/editor/posts.*`・`editor.mjs`（ページの一覧と書き出し先の欄）

## 1. 何をするか

決まった URL に置く複数のページ（トップ・`exhibitors.html`・`en/index.html` のような）を、WGE で書いて公開できるようにする。

- ページごとに、書き出す場所（書き出し先）を決める（§3）
- WGE が書いたファイルの台帳を持つ。台帳に無いファイルは、消さない・上書きしない（§4）
- すべてのページに、共通のヘッダーとフッターを差し込む（§5）

ブログ（blog.md）はこれまでどおり動く。サイトの中にブログを置く形は次の段にする（§8）。

## 2. 設定

| 変数 | 内容 |
|---|---|
| `WGE_SITE_NAME` | あるときだけ「サイト」になる。1 行で 120 文字まで。共有の印の `og:site_name` とエディタの表示に使う |

- `WGE_BLOG_TITLE` と同時には使えない（何も配らず 503）。
- どちらも無ければ、前と同じ動き（`top` は `index.html`、ほかは `{id}/index.html`、台帳なし）。
- `/api/ping` は、サイトなら `site: true`・`siteName` も返す。

## 3. 書き出し先

- `page_meta` に `path` の列を足す（無ければ NULL。前の版のデータベースには、開いたときに足す）。
- 書き出し先の形
  - 英小文字・数字・ハイフンの名前を `/` でつなぎ、最後は `.html`。フォルダは 3 段まで（`a/b/c/x.html`）、名前は 1 つ 64 文字まで
  - 最初のフォルダに `media` と `blog` は使えない（WGE が使う名前）。`style.css` も WGE が書く
  - ほかのページと同じ書き出し先は使えない（削除した記事も含む。元に戻したときにぶつかるため）。409 `path-taken`
  - 外れたら 422 `invalid-path`
- 書き出し先は、題名と一緒に `load` の `meta` と `meta` で渡す。サイトでは `meta` の `date` は要らない（渡せば検査する。無ければ空として持つ）。
- **書き出し先の変更は、次の公開のときに効く。** `meta` は書く権限だけで通る（server.md §6）。公開中のページの URL を、公開の権限なしに動かせないようにするため。`meta` で公開中のページを書き直すときは、いま書いてある場所に書く。
- `GET /api/pages` の各ページは `path`（次の公開で書く場所）と `livePath`（いま書いてある場所。公開していなければ null）を返す。並びは `top` が先で、あとは書き出し先の順。
- `top` の書き出し先は既定で `index.html`。
- 新しいページを作る `load` で、すでに題名などを持つ id を渡したら 409 `exists`（別のページを開いてしまわないように）。

### 3.1 深さで変わる URL

サイトのページは深さ（`index.html` は 0、`en/index.html` は 1）が違うので、書き出しのときに次の値を、そのページから見た相対の URL に直す。ヘッダーとフッターも、差し込むページの深さで直す。

| ソースの値 | 深さ 0 | 深さ 1 | 深さ 2 |
|---|---|---|---|
| `/exhibitors.html`（サイトの根から） | `exhibitors.html` | `../exhibitors.html` | `../../exhibitors.html` |
| `/` | `./` | `../` | `../../` |
| `../media/x.png`（エディタが入れる画像） | `media/x.png` | `../media/x.png` | `../../media/x.png` |

- 対象は `url` の型の属性（`Button` の `href`、`Image` の `src`、`Link` の `href`）だけ。Html の箱の中身は直さない（無害化だけ）
- 根からの書き方を公開ページに残さないので、試験の場所のように、サイトをサブパスに置いても切れない
- `//` で始まる値と、`https:` などの方式のある値はそのまま
- スタイルシートは `style.css` を同じように指す（深さ 1 なら `../style.css`）
- canonical と `og:url` は `WGE_SITE_URL` に書き出し先をつないだもの。最後の `index.html` は外す（`en/index.html` → `<サイト>/en/`）。`og:image` は直したあとの値を、そのページの URL から解く
- ブログでない、サイトでもないとき（今までの動き）は直さない

## 4. 書いたファイルの台帳

- 表 `site_files`（`path`・`page`）に、WGE が書いたファイルを持つ。`page` はページの id、`style.css` は空
- 公開の前に、書き出し先を確かめる。ファイルがあって台帳に無ければ（WGE が書いていないファイル）、公開しないで 409 `path-occupied` を返す。`style.css` も同じ
- 公開したページの書き出し先が前と違えば、前のファイル（台帳にあるもの）を消して、台帳から外す
- 公開を取り消して何も公開していない状態になれば、そのページのファイルを消して台帳から外す
- ファイルを消したあと、空になったフォルダは消す（サイトの根は残す）。台帳に無いファイルは、どの場合も消さない

## 5. 共通の部分（ヘッダーとフッター）

- 予約した id の `part-header`（ヘッダー）と `part-footer`（フッター）を、ほかのページと同じ下書き・公開・版の仕組みで持つ。エディタも同じ画面で直す
- 共通の部分を公開・公開の取り消しをすると、公開中のすべてのページを書き直す。どのページにも、共通の部分の**公開中の版**だけを入れる（下書きは出ない）
- 公開の権限の要る道（`publish`・`undo-publish`）でだけ、サイトの全ページが変わる。前段の許可の仕組み（server.md §6）を変えずに済む
- 共通の部分には題名も書き出し先も無い。`meta` は 409 `part`、`delete` は 409 `part`
- `GET /api/pages` の `pages` には出さず、`parts`（id・loaded・published・savedAt）で返す
- `part-` で始まるほかの id は、サイトでは 404
- 書き出し: `renderPage` の `header`・`footer`（rendering.md §5）。`<main>` の前に `<header class="wge-site-header">`、後ろに `<footer class="wge-site-footer">`。渡さなければ、出力は前と 1 バイトも変わらない

## 6. エディタ

- 一覧（`posts.html`）は、サイトなら「ページの一覧」になる。題名と書き出し先で新しいページを作り、各ページの書き出し先と状態（公開中・下書き・次の公開で移る）を出す。上に「共通の部分」（ヘッダー・フッター）を置く
- エディタの上の欄は、サイトなら題名・書き出し先・説明文（日付は無い）。共通の部分では欄を出さない
- 「サイトを見る」は、いま書いてある場所を開く

- `test.php`（part 6）: 書き出し先の検査、重複、深さ 0・1・2 の URL の直し方、台帳（よそのファイルを消さない・上書きしない、フォルダの場所にファイルがあるとき、移したときの古いファイル、取り消し、空のフォルダ）、共通の部分（公開で全ページが変わる・下書きは出ない・取り消し・共有の画像はページのものだけ）、`meta` で書き出し先が動かないこと、前の版のデータベースへの列の追加。PHP 8.3.36 と 8.5.12 で 223 件が通過
- 書き出し器の共通テストデータ（JS と PHP）: ヘッダーとフッター、空のヘッダー、フッターの Html の無害化。150 件が通過
- ブログ（part 5）と今までの動き（part 2）の検査は、中身を変えずに通した
- `posts-core.test.mjs`: 書き出し先の整え方（`/Exhibitors` → `exhibitors.html`、`en/` → `en/index.html`）、ページの id、共通の部分の雛形が読み直せること
- Playwright（Chromium）で開発用サーバー（`run-dev.sh` の 4 つ目の引数にサイトの名前）を操作した
  - 一覧がサイトの言葉になり、日付の代わりに書き出し先の欄が出る
  - 使えない書き出し先と、使われている書き出し先は、一覧の下に理由が出て作られない
  - ヘッダーを公開すると、公開中の 2 ページに入り、トップへのリンクがそれぞれの深さで直っている
  - 公開中のページの書き出し先を変えると、欄の横に「公開中は …。次の公開で移ります」が出て、中身が同じでも「公開」を押せる。公開すると新しい場所が 200、古い場所が 404 になる
  - 一覧を 1280px と 375px で表示し、ui-audit で小さすぎる押し領域・ラベルの無い入力・横はみ出しが 0
- 途中で見つけて直したこと: 書き出し先だけを変えたページは、中身が公開中と同じため「公開済み」で押せず、移せなかった

## 8. まだのこと

- サイトの中のブログ（`blog/` に記事と目次。共通の部分も入れる）
- テーマ（G2）、ナビやヒーローなどの部品（G3）、一覧のデータ（G4）、日英の対訳（G5）
- エディタのプレビューに、共通の部分を出すこと
- 書き出し先を変えたとき、古い URL から新しい URL へ転送すること（静的なサイトなので、いまは古い URL が 404 になる）
